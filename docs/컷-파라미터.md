# 쉼을 얼마나 남길 것인가

**정본은 `src/cut_planner.py` 의 `PARAMS` 다.** 이 문서의 숫자는 설명용이고,
값을 확인할 때는 코드를 읽어라. 예전에 문서에 베껴 적은 옛 값(0.45/0.80)이
낡은 채로 남아 헷갈린 적이 있다.

코드 주석에 1차부터 5차까지의 학습 기록이 그대로 남아 있다. 값을 바꾸려면
그 주석부터 읽어라. 주석 안의 "2차시" "3차시" 는 이 도구를 처음 만든 원격연수
강의를 가리킨다.

## 지금 값 (2026-08 기준)

| 항목 | 값 | 뜻 |
|---|---|---|
| `max_silence_mid` | 0.20초 | 문장이 안 끝났는데 생긴 쉼. 뚝뚝 끊기는 느낌의 주범 |
| `max_silence_end` | 0.70초 | 문장이 끝난 자리의 쉼. 문단 구분이 여기서 들린다 |
| `max_silence_scene` | 1.20초 | 장면이 바뀌는 컷. 0.47초짜리 페이드가 말 위에 겹치면 안 된다 |
| `tail_ratio` | 0.45 | 남긴 쉼을 앞말 뒤 45 : 뒷말 앞 55 로 나눈다 |
| `min_saving` | 0.15초 | 이만큼도 못 줄이면 자르지 않는다 (잔컷 방지) |
| `start_lead` / `end_tail` | 0.30 / 0.80초 | 영상 맨 앞뒤 여유 |
| `delete_overlap` | 0.5 | 발화 구간이 삭제 범위에 절반 이상 걸리면 통째로 뺀다 |

## 왜 '상한선' 방식인가

예전엔 "1초 넘는 공백을 0.55초로 줄인다"였는데, 0.99초 쉼은 그대로 두고
1.01초 쉼은 0.55초로 줄여서 **더 길었던 쉼이 더 짧아지는 역전**이 생겼다.
지금은 모든 쉼을 상한까지만 깎으므로 항상 단조적이다.

## 왜 문장 중간과 문장 끝을 나누는가

전부 같은 값으로 깎으면 문장 안에서 말이 뚝뚝 끊긴다. 사람이 직접 손본 편집본을
역산했더니 문장 중간 중앙값 0.60초, 문장 끝 0.80초로 갈렸다. 낭독 연구의
쉼표 뒤(0.38~0.67초)와 마침표 뒤(0.81~1.24초) 범위와도 맞는다.

문장 중간 0.20 과 문장 끝의 비가 3:1 아래로 내려가면 문단 구분이 안 들린다.
문장 끝을 더 내리려면 0.50 이 한계로 보인다.

## 쉼이 길다는 말이 나오면

**파라미터부터 만지지 마라.** 상한값과 체감은 다르다. 편집본에서 실제로
들리는 쉼을 문장 중간과 문장 끝으로 갈라 먼저 재라. 실측 한 번에 원인이
갈렸던 적이 있다.

```
문장 중간 377곳  중앙 0.20초  최대 0.30초  합계 1.3분
문장 끝   230곳  중앙 0.80초  최대 0.90초  합계 3.0분   ← 전체 쉼의 70%
```

문장 중간은 이미 상한에 붙어 있어 더 깎을 게 없었다. 길이는 문장 끝에 몰려
있었고, 문장 끝만 내려 46초를 줄였다.

## 강의가 아닌 영상이라면

콘텐츠 유형별 권장 임계는 대담 0.8~1.2초, 1인 토킹헤드 0.5~0.7초,
튜토리얼 0.3~0.5초다. 90분짜리 원격연수는 대담 쪽에 가깝다.

교육 영상은 학습자가 정보를 통합할 처리 시간이 필요하다. 절 경계의 쉼은 단어
인지 속도와 명제 회상률을 높인다. 자동 컷이 어색해지는 주된 원인은 너무 바짝
자른 것이다(auto-editor 기본 마진도 0.2초).

참고: [Frontiers in Psychology 2022](https://www.frontiersin.org/journals/psychology/articles/10.3389/fpsyg.2022.778018/full),
[auto-editor](https://github.com/WyattBlue/auto-editor)

## 값을 바꿨으면

반드시 수치로 확인하고 커밋한다. 사용자가 손본 편집본을 정답지로 삼아 재현율과
정밀도를 잰다.

```bash
python src/diff_user_cuts.py <드래프트> <keep_ranges.json> <words.json> --json <정답지.json>
python src/find_repeat_retakes.py <words.json> <out.json> --eval <정답지.json>
```
