# 4단계 — 청크 분석 (LLM)

`make_llm_transcript.py` 가 전사본을 450단어씩(앞뒤 50단어 겹침) 잘라
`<이름>_chunks/chunk_NN.txt` 로 내놓는다. 청크마다 서브에이전트를 하나씩
병렬로 띄워 아래 지시문을 주고, 받은 JSON 을
`<이름>_results/result_NN.json` 으로 저장한다.

파형이 못 하는 몫이 여기다. 어디를 자를지는 VAD 가 정하고, **무슨 말인지**는
이 단계가 판단한다.

## 입력 형식

```
# 청크 2/8 | 단어 인덱스 400~849 | 시간 471s~1223s

### t=471.5s
400:여러분 401:안녕
--- 무음 50.4s ---
### t=522.5s
402:그러면 403:메뉴에서 404:새프로젝트를 405:눌러 406:줍니다.
```

단어마다 붙은 숫자가 전역 인덱스다. 삭제·교정 지시는 전부 이 인덱스로 적는다.
`### t=` 는 그 줄 첫 단어의 원본 시각, `--- 무음 ---` 은 0.8초 이상의 공백이다.

## 지시문 (서브에이전트에 그대로 준다)

> 강의 녹화 전사본의 한 토막이다. 두 가지만 판단해서 JSON 으로 내놓아라.
>
> **1. 삭제할 구간 (deletions)** — 말하다 막혀서 다시 말한 대목을 찾는다.
> 같은 내용을 두 번 이상 말했으면 **완성도 높은 마지막 테이크를 남기고 그 앞의
> 실패 테이크를 지운다.** 문장을 시작했다가 끊고 다시 시작한 자리, 단어를
> 더듬은 자리, 말을 물린 자리("아 아니고", "다시 할게요")가 대상이다.
>
> - 지우는 범위는 실패 테이크의 첫 단어부터 마지막 단어까지다.
> - **내용이 다르면 지우지 않는다.** 비슷한 표현이 두 번 나와도 서로 다른
>   항목을 가리키면 남긴다. 지우면 내용이 사라진다.
> - 진짜 인사말은 남긴다. 영상 끝의 "감사합니다" 는 재발화가 아니다.
> - 확신이 서면 `"confidence": "high"`, 애매하면 `"medium"`. high 만 자동으로
>   잘린다. medium 은 영상에 남고 검수 보고서에 "검토 필요" 로 올라간다.
>   **애매하면 medium 을 쓴다.** 잘못 자르면 되돌릴 수 없다.
> - STT 가 지어낸 말(조용한 구간의 「시청해주셔서 감사합니다」
>   「~및 광고를 포함하고 있습니다」)은 잘라낼 소리가 없다. 지우려면
>   `"kind": "hallucination"` 을 달아라. 영상은 그대로 두고 자막에서만 뺀다.
>
> **1-2. 사람이 최종 편집에서 지운 말 (medium 으로만)** — 재발화는 아니지만 강사가 최종
> 편집에서 거듭 지운 말이다. 찾으면 `"confidence": "medium"` 으로 적고 `reason` 앞에 유형을 붙인다.
> 자동으로 잘리지 않고 드래프트에 「삭제 후보」 글자로 뜬다. 강사가 보고 정한다.
>
> - **같은 뜻 되풀이**: 앞 문장을 다른 말로 한 번 더 한 것(「…다 되돌아갑니다」 바로 뒤
>   「다 되돌아가는 것을 확인할 수 있습니다」). 뒤쪽을 후보로
> - **진행 안내**: 화면 흐름만 알리는 말(「두 번째 순서입니다」「화면으로 보시는 게 이해가 빠르겠습니다」
>   「여기까지가 …입니다」「…한 이유가 있습니다」「우선 이를 살펴보기 전에」)
> - **화면 글 소리 내 읽기**: 입력하거나 화면에 뜬 프롬프트·결과 글을 길게 그대로 읽는 말
> - **첫 인사 겹침**: 오프닝을 따로 붙이는 강의에서, 본편 첫머리의 인사·차시명·「시작하겠습니다」
> - **곁가지**: 없어도 흐름이 이어지는 보충 설명(요금 등급, 여담, 「팁을 드리자면」)
> - **사실과 다른 말**: 화면과 다른 방향·메뉴 이름(「우측 상단」인데 화면은 왼쪽 위)은 `reason` 에
>   「확인 필요」를 붙인다. 지우기보다 강사 판단이 먼저다
>
> 근거: 강의 네 편의 초안과 강사 최종본을 견줬을 때 강사가 더 지운 말 93덩어리 대부분이 이 여섯 유형이었다.
> 글자 패턴만으로 찾으면 맞는 것이 15%라, 문맥을 읽는 이 단계에서 판단한다(2026-09-28).
>
> **2. 자막 교정 (corrections)** — 받아쓰기가 틀린 단어를 고친다. 소리는
> 그대로 두고 자막 글자만 바뀐다.
>
> - 고유명사·전문용어·메뉴 이름 위주로 본다.
> - 말투나 문장을 다듬지 마라. 들린 대로 적힌 것이 맞으면 그대로 둔다.
> - 확실하지 않으면 손대지 않는다.
>
> 청크 경계 앞뒤 50단어는 옆 청크와 겹친다. 겹친 자리도 그냥 판단해라.
> 중복은 병합 단계가 걸러낸다.
>
> 설명 없이 JSON 만 내놓아라.

## 출력 형식

```json
{
  "deletions": [
    {
      "from_i": 217,
      "to_i": 220,
      "text": "그러면 우리가 이미지 생성,",
      "reason": "문장을 중간에 끊고 뒤에서 다시 말함(229~)",
      "confidence": "high"
    }
  ],
  "corrections": [
    {"i": 51, "orig": "사파를", "fixed": "삽화를"},
    {"i": 88, "orig": "재본", "fixed": "제본"}
  ]
}
```

`deletions` 도 `corrections` 도 없으면 빈 배열을 넣는다. `reason` 은 나중에
검수 보고서에 그대로 실리므로 사람이 읽을 문장으로 쓴다.

## 병합

```bash
python src/merge_analysis.py <이름>_results <이름>_analysis.json <이름>_retakes.json
```

겹침 구간의 중복 삭제를 하나로 합치고, high 만 `retakes.json` 으로 내보낸다
(컷 계획에 자동 적용). medium 은 `analysis.json` 의 review 목록으로 남아
보고서에 실린다. corrections 는 인덱스 기준으로 중복을 제거한다.

## 이 단계가 놓치는 것

**전사본에 안 보이는 재발화가 있다.** Whisper 는 같은 문장이 연달아 나오면
반복 억제 필터가 하나를 지운다. 그래서 청크 분석만으로는 못 찾는다.
3단계(`transcribe_per_segment` + `find_hidden_retakes`)를 반드시 같이 돌린다.
같은 문장을 열 번 다시 말한 구간이 통짜 전사본에는 한 번만 적혀 있던 사례가 있다.
