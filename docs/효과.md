# 효과: 교안 애니메이션 · 강조 박스 · 장면 전환 · 작은 글씨 확대

컷이 끝난 러프컷에 얹는 효과다. 한 화면이 오래 멈춰 있으면 지금 어디를 말하는지 알기
어렵고 지루하다. 말하는 순서대로 항목이 나타나고, 가리키는 곳에 상자가 뜨고, 작은 글씨는
커지게 한다.

## 원칙

- **효과는 원본 시각에 묶는다.** 계획 파일에 `src: [시작, 끝]` 을 원본 mp4 초로 적는다.
  컷이 바뀌어도 다시 붙이면 제자리로 간다(`timemap.py`). 편집본 시각으로 적으면 오프닝을
  끼우거나 컷 하나만 고쳐도 전부 어긋난다
- **캡컷 스키마를 짓지 않는다.** 도형·애니메이션·전환은 사람이 캡컷에서 직접 만든 드래프트에서
  통째로 복제한다. 어느 드래프트를 참조하는지는 프로젝트 폴더의 규격 문서에 적는다
- **화면을 바꾸는 효과(교안 단계, 확대)는 원본에 굽는다.** 블러·크로마키와 같은 방식이다.
  원본과 시각이 1:1 인 새 파일을 만들므로 컷 계획을 그대로 쓴다. 굽는 것은 한 번에 한다.
  따로 구우면 3시간짜리 원본을 두 번 인코딩한다
- 효과마다 계획 파일(JSON)을 남기고, **확인 그림을 전부 눈으로 본다.** 숫자 검사만으로는
  엉뚱한 곳에 붙은 상자를 못 잡는다

## 1. 교안 애니메이션 (나타내기)

### 교안 파일에 넣기

```bash
python src/slide_blocks.py <교안.pptx> [장번호...]          # 단계 후보
python src/ppt_anim.py <교안사본.pptx> <계획.json> <새이름.pptx>
(발표 자료 비교 도구로 교안사본과 새이름을 대조)          # 애니메이션 말고 차이 0
```

- 클릭할 때 · 밝기 변화 · 0.5초 한 종류. 한 클릭 = 대본 한 문단. 장당 3~6단계(짧은 장은 2단계)
- 제목·장식·액자는 처음부터 떠 있다. 표지·간지·참고 문헌·차시 예고에는 넣지 않는다
- `slide_blocks` 는 큰 도형을 카드로 보고, 그 안에 중심이 든 도형을 카드에 붙인 뒤
  위에서 아래, 왼쪽에서 오른쪽으로 순서를 매긴다. **대본 순서가 다르면 대본을 따른다.**
  대본에서 읽지 않는 인용은 그 말을 할 때(대개 마지막) 붙인다
- 원본은 고치지 않는다. 사본에 써서 새 이름으로 둔다
- 파워포인트로 열어 장마다 클릭 수와 길이(0.5초)를 센다. python-pptx 로 저장한 파일이
  파워포인트에서 안 열린 적이 있다
- 저장하면 파일이 몇 MB 작아진다. 압축 방식만 다르다. 부품 수와 임베드 글꼴이 같은지 본다

### 이미 찍은 영상에 나타내기 굽기

녹화할 때 애니메이션이 없었으면 영상에서 만든다.

```
export_slides.py   교안을 장마다 PNG 로 (파워포인트 렌더)
render_builds.py   단계마다 아직 안 나온 도형을 숨긴 렌더
compose_builds.py  녹화 화면 + 숨길 자리만 렌더 바탕 = 단계 화면
bake_builds.py     장이 떠 있는 원본 구간에 단계 화면을 덮고 0.5초 페이드
```

- **보이는 글자는 녹화 화면 그대로 쓴다.** 이 PC 의 파워포인트가 교안에 든 글꼴(캔바 글꼴 등)을
  못 그리면 렌더 글자가 다른 글꼴로 바뀐다. 렌더는 숨길 자리의 바탕으로만 쓴다
- 녹화 화면은 그 장이 떠 있는 동안 **남는 구간 안에서** 7장을 뽑아 중앙값을 낸다. 커서가 지워진다
- 나타날 시각은 그 항목을 말하기 시작하는 덩어리 시각이다. 잘려 나간 곳이거나 블록 끝
  0.6초 안이면 페이드가 잘리므로 다음 블록 시작 0.03초 뒤로 옮긴다

숨긴 자리에 흐린 테두리가 비치면 안 된다. 세 번 고쳤다.

| 증상 | 까닭 | 지금 |
|---|---|---|
| 숨긴 자리에 흐린 네모 | 화면 전체에 밝기 식 하나를 맞춰 흰색이 255 → 254 | 숨길 자리 바로 바깥 띠에서 잰 차이를 **한 값으로** 더한다 |
| 카드·탭 모양의 1~2단계 선 | 묶음마다 따로 맞춰 255 인 곳과 254 인 곳의 경계가 도형 테두리를 따라 남았다. 섞는 가장자리를 버림해서 254.9 가 254 가 됐다 | 한 값 · 반올림 · 숨길 자리를 도형 상자 + 12px 로(녹화에 카드 밖 7px 까지 옅은 그림자) |
| 나오기 전 상자 윗부분이 보임 | 이미 나온 글상자의 틀이 글자보다 훨씬 커서 아래 상자를 덮었고, 그 틀 안은 숨기지 않았다 | 전체 렌더와 단계 렌더가 다른 곳(숨길 도형이 그려지는 곳)은 틀 안이어도 숨긴다 |

검사 두 줄: 숨길 도형이 그려지는 곳에서 렌더와 40 넘게 다른 픽셀 0, 흰 숨김 자리에서
어두워진 픽셀 수. 대비를 40배로 늘린 그림으로도 본다. 1단계 차이는 인코딩하면 안 보인다.

## 2. 강조 박스

```bash
python src/apply_highlights.py <계획.json> <참조 드래프트> [--dry]
```

사각형과 등장 애니메이션을 참조 드래프트에서 통째로 복제하고 크기·위치만 바꾼다.
배율 K=2.64 는 캡컷 렌더를 재서 얻은 값이다. 어긋나 보이면 추측하지 말고 같은 방법으로 다시 잰다.

교안 장

- 카드·띠: 그 단계가 나타나고 0.5초 뒤(페이드가 끝난 뒤)부터 다음 단계가 나타날 때까지.
  도형 좌표 + 바깥 12px
- 프롬프트처럼 긴 글: 글줄을 녹화 화면에서 픽셀로 찾아 그 줄을 읽는 동안. 글자 상자 + 좌우 16px · 위아래 15px
- 말 없이 보여 주는 장, 사진, 말하지 않는 카드에는 넣지 않는다

실습 화면

- 대본에서 화면의 특정 부분을 가리키는 말('~ 버튼을 클릭', '우측 상단의 ~', '~ 칸에')을 찾는다
- 그 순간 프레임을 격자와 함께 모아 보고 대략 자리를 짚는다. 도구가 그 안에서 바탕과 다른
  픽셀(글자·단추·칸 테두리)의 경계를 찾아 16/15px 여백을 붙인다
- **녹화에 강사가 직접 그린 빨간 상자가 있는 순간은 넣지 않는다**
- 상자 부분 화면이 기준 프레임과 달라지면(대화상자가 닫히거나 쪽이 바뀌면) 거기서 끝낸다.
  요소가 늦게 뜨면 뜬 뒤 시작한다. 1초보다 짧으면 화면이 그대로인 동안 1초까지 늘린다
- 드롭다운 항목처럼 0.4초만 떠 있는 것에는 걸 수 없다. 그 메뉴를 여는 단추에 건다
- 누르자마자 화면이 넘어가는 단추는 뺀다
- 격자 그림을 여러 칸(960x540)으로 모아 보면 **칸 안 좌표를 두 배** 해야 원본 좌표다. 한 번 틀렸다
- 확대 구간 안의 상자는 확대 화면 좌표로 옮긴다(`bake_zoom.box_in_zoom`). 확대가 멈춰 있는 동안만 둔다

확인 그림: 상자마다 시작·끝 프레임에 상자를 그려서 전부 본다.

## 3. 장면 전환

```bash
python src/apply_transitions.py <계획.json> [--dry]
```

사용자가 손으로 넣은 전환은 'B 페이드' 0.467초(is_overlap false) 한 가지였다.
넣은 곳을 앞뒤 화면으로 대조해 규칙을 얻었다.

| 넣는다 | 안 넣는다 |
|---|---|
| 슬라이드 ↔ 실습 화면 | 슬라이드 → 슬라이드 |
| 실습 중 다른 앱·다른 화면으로 넘어가는 컷 | 같은 앱 안에서 팝업이 뜨고 닫히거나 상태만 바뀌는 컷 |
| 인트로 ↔ 오프닝 ↔ 본편(납품 가이드에 있으면) | |

실습 → 실습은 화면 차이 수치로 안 갈린다. 내용을 보고 정하고, 계획 파일에 까닭을 적는다.
전환이 붙는 컷은 쉼을 1.2초 남긴다(`cut_planner` 의 장면 컷). 페이드가 말 위에 겹치지 않게 한다.

## 4. 작은 글씨 확대

```bash
python src/bake_zoom.py <계획.json> --preview     # 확대가 다 된 순간 한 장씩
```

- 굽기는 교안 단계와 한 판으로 한다(`bake_builds.py` 계획에 `zooms` 를 넣는다)
- 관심 영역이 화면의 90% 가 되게 키운다. 최대 2배. 0.4초 동안 부드럽게 들어가고 나온다
- 고르는 곳: 코드 설명, 입력 칸, 표·시트 내용처럼 **말로 그 글을 읽거나 짚는 동안 화면이
  크게 움직이지 않는 곳**. 화면 전체를 오가며 누르는 곳은 확대하면 누르는 곳이 잘린다
- 움직임은 남는 블록 안에서 한다. 첫 블록 시작에서 들어가고 마지막 블록 끝 0.4초 안에서 나온다.
  잘린 곳에서 움직이면 안 보이고 뚝 튄다
- 캡컷 마스크 확대(`apply_mask.py`)는 세그먼트 통째로 걸리고, 밖이 검게 비고, 들어가고 나올 때
  뚝 끊긴다. 굽는 쪽을 쓴다

## 5. 순서

```
컷 계획 확정 → 교안 단계 화면 만들기·검사 → 확대 계획 → 한 판으로 굽기(교안 단계 + 확대)
→ 구운 파일을 소재로 드래프트 빌드 → 장면 전환 → 강조 박스 → 진단·소리 검사 → 스냅샷
```

3시간 녹화 기준으로 굽기가 40분쯤 걸린다(단계 화면 26구간 20분, 전체 인코딩 15분).
굽는 동안 박스 계획과 확인 그림을 만든다.
