# 납품 규격 점검 — 프로필 만드는 법

`check_guidelines.py` 는 규격을 코드에 박지 않고 **프로필 JSON** 으로 받는다.
플랫폼마다 길이도 파일명도 자막 정책도 다르기 때문이다. 프로필 한 장을 쓰면
그 플랫폼 검사기가 된다.

```bash
python src/check_guidelines.py <영상.mp4> [영상2.mp4 ...] \
    --프로필 <프로필.json> \
    --드래프트 <캡컷드래프트이름> \
    --전사 <words.json> \
    --보고서 <점검보고서.md>
```

셋(영상·드래프트·전사) 중 있는 것만 줘도 된다. 안 준 것은 '건너뜀' 으로 적힌다.

## 무엇을 볼 수 있고 무엇을 못 보나

기계가 세는 것과 사람이 보는 것을 갈라 놓는 것이 이 도구의 요점이다.

| 본다 | 어디서 |
|---|---|
| 해상도·프레임레이트·코덱·컨테이너 | 영상 파일 |
| 길이가 목표 범위 안인가 | 영상 파일 |
| 파일명이 규칙에 맞는가, 있어야 할 파일이 다 왔는가 | 영상 파일 |
| 오디오 트랙 유무, 통합 라우드니스, 파일 사이 음량 차이 | 영상 파일 |
| 자막이 허용 구간 밖에 있는가, 한 줄 글자 수, 줄 수 | 캡컷 드래프트 |
| 금지 표현이 자막에 남아 있는가 | 캡컷 드래프트 |
| 차시 언급, 금지 표현, 슬레이트 잔존 | 전사본 |

못 보는 것은 자막이 화면을 가리는지, 블러가 빠졌는지, 크로마키에 파랑이
남았는지, 학습목표가 행동동사인지 같은 것이다. 프로필의 `직접확인` 에 적어
두면 보고서 끝에 체크박스로 실린다. **못 보는 것을 안 보이게 숨기지 말고
목록으로 남기는 것**이 이 도구가 하는 일의 절반이다.

## 프로필 뼈대

```json
{
  "이름": "○○ 원격연수",

  "영상": {
    "가로": 1920, "세로": 1080, "fps": 30,
    "코덱": "h264", "컨테이너": "mp4"
  },

  "파일": [
    {
      "종류": "001 (본연수)",
      "식별": "_001",
      "이름": "^\\d{2}_\\d{8}_001\\.mp4$",
      "길이초": [1200, 1500],
      "오디오": "있음"
    }
  ],

  "라우드니스": { "범위": [-24.0, -18.0], "파일간차이": 2.0 },

  "자막": { "허용구간": [[0, 85]], "한줄글자": 25, "최대줄": 2 },

  "금지표현": [
    { "이름": "'학생들'", "표현": "학생들",
      "고침": "'학생' 으로 쓴다", "어디": ["자막", "말"] }
  ],

  "직접확인": [ "작업표시줄이 블러 처리되었는가" ]
}
```

전부 선택 항목이다. 없는 칸은 검사하지 않는다. 규격을 아직 모르는 항목은
넣지 말고 비워 둔다. **모르는 값을 그럴듯하게 채우면 검사기가 통과를 내주고,
그 통과는 거짓말이다.**

## 칸 설명

### 파일

`식별` 과 `이름` 은 다른 일을 한다.

- `식별` — 이 파일이 어느 종류인지 가르는 **느슨한** 표현(`_001` 처럼)
- `이름` — 파일명 규칙을 지켰는지 따지는 **엄격한** 표현

둘을 하나로 쓰면 이름이 조금만 틀려도 종류를 못 가려서 길이 검사까지 통째로
건너뛴다. 정작 이름이 틀렸다는 것만 알려 주고 나머지는 침묵하는 셈이다.
`식별` 이 없으면 `이름` 을 대신 쓴다.

`오디오` 는 `"있음"` 또는 `"없음"`. 오디오 스트림이 있는지만 본다.
**말인지 음악인지는 기계가 못 가른다.** BGM 만 깔아야 하는 파일이면
`직접확인` 에 "나레이션이 없는지 들어 본다"를 넣는다.

### 자막

`허용구간` 은 자막이 있어도 되는 편집본 시각 구간이다. `[[0, 85]]` 는 앞
85초 안에만 자막을 허용한다는 뜻이다. 오프닝에만 말자막을 다는 규격에 쓴다.
자막 전체를 허용하려면 이 칸을 빼면 된다.

**캡컷 드래프트를 읽는다.** 이미 내보낸 mp4 의 번인 자막은 못 읽는다.
내보내기 전에 돌려야 고칠 수 있다.

### 금지표현

`표현` 은 정규식이다. `어디` 는 `자막`(드래프트) · `말`(전사본) 중 검사할
곳을 고른다. 발음은 같은데 자막 표기만 문제인 항목은 `["자막"]` 만 준다.

`고침` 은 보고서에 그대로 실린다. 무엇이 잘못됐는지가 아니라 **무엇으로
바꾸라는 것인지**를 적는다.

말 검사는 전사본을 문장으로 이어 붙여서 본다. 그래야 '앞 차시에서' 처럼 두
낱말에 걸친 표현이 잡힌다.

### 라우드니스

`범위` 는 통합 LUFS. `파일간차이` 는 같이 낸 파일들 사이의 최대 허용 차이(LU)다.
한 편은 크고 다른 한 편은 작으면 시청자가 볼륨을 다시 만지게 된다.

기준이 가이드에 없으면 **이미 통과한 영상을 재서** 범위를 잡는다.

## 언제 돌리나

두 번 돌린다.

1. **컷 편집 드래프트가 나온 직후** — 자막과 말 검사가 여기서 값을 한다.
   지금 고쳐야 싸다.
2. **최종 mp4 를 내보낸 뒤, 제출 전** — 영상 규격과 길이를 본다.

## 결과 읽는 법

| 표시 | 뜻 |
|---|---|
| ○ 통과 | 기준을 지켰다 |
| ✕ 실패 | 고쳐야 한다 |
| △ 확인 | 기준을 벗어났지만 상황에 따라 괜찮을 수 있다 (라우드니스 등) |
| · 건너뜀 | 검사할 입력을 안 줬거나, 프로필에 기준이 없다 |

**건너뜀이 많으면 통과 건수를 믿지 마라.** 안 본 것이 많다는 뜻이다.
