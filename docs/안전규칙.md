# 캡컷 드래프트를 깨뜨린 사고들

전부 실제로 겪었다. 규칙만 읽고 넘기면 같은 사고가 반복되므로 무슨 일이
있었는지까지 적는다. SKILL.md 의 "절대 어기면 안 되는 것" 이 이 문서의 요약이다.

## 1. 캡컷이 켜져 있는데 드래프트를 건드렸다

편집 중이던 프로젝트가 통째로 사라졌다. 캡컷은 열려 있는 프로젝트 폴더가
밖에서 바뀌면 사본을 만들거나 메모리 상태로 되돌려 저장한다. 30분치 작업이
날아갔다.

도구가 `tasklist` 로 CapCut.exe 를 확인하고 스스로 멈춘다. 이 검사를 지우지 마라.

## 2. 캡컷 스키마 값을 추측해 넣었다

비디오 material 의 `extra_type_option` 을 추측으로 1 로 넣었다. 캡컷은 이 값을
"이 클립의 소리를 별도 트랙으로 떼어냈다"로 읽어 클립을 음소거한다. 떼어낸
트랙이 없으니 강의 두 편이 통째로 무음이 됐고, `draft_content.json` 을 읽으면
volume 1.0 · has_audio True 라 멀쩡해 보여서 하루 동안 아무도 몰랐다.

- 비디오 material 의 `extra_type_option` 은 **0** 이다. `has_sound_separated` 도
  같은 뜻이지만 캡컷이 실제로 읽는 쪽은 `extra_type_option` 이다.
- 판단 기준은 **캡컷이 직접 만든 정상 드래프트**다.
  `verify_draft_audio.py <드래프트> --compare <정상드래프트>` 로 대조한다.
- 고칠 때도 마찬가지다. 그럴듯한 필드 하나만 되돌리고 끝내지 마라. 이 버그도
  `has_sound_separated` 만 되돌렸다가 증상이 그대로여서 두 번 고쳤다.

이미 넘긴 드래프트가 무음이면 `repair_sound_separated.py` 로 되돌린다. 캡컷은
드래프트를 열 때 하위 폴더와 `Timelines` 에 `draft_content.json` 을 여러 벌
만들므로 전부 고쳐야 한다.

**예외**: 사용자가 일부러 오디오를 분리해 둔 클립(재녹음을 얹은 자리)이 있으면
수리를 돌리지 마라. 원본 소리가 되살아나 재녹음과 겹쳐 메아리가 된다.

## 3. 드래프트를 폴더 이름으로 찾았다

캡컷은 프로젝트 이름이 겹치면 폴더 뒤에 `(1)` 을 붙여 바꿔친다. 그런데
`draft_content.json` 안의 소재 경로 일부는 **절대경로**라 따라오지 않는다.
영상 425개와 사용자가 재녹음한 오디오 20개가 통째로 끊겼다. 사용자에게는
"작업물이 사라진" 것으로 보였다.

- 드래프트 이름의 진짜 근거는 `draft_meta_info.json` 의 `draft_name` 이다.
  여러 폴더가 걸리면 고르지 말고 멈춘다(`draft_doctor.resolve`).
- 붙이기 **전에** `draft_doctor.py 진단` 으로 끊긴 경로가 0인지 본다.
  붙인 **뒤에도** 한 번 더 본다.
- 끊겼으면 `draft_doctor.py 수리 <드래프트>`. 타임라인뿐 아니라
  `draft_meta_info.json` 의 미디어 목록까지 같이 고쳐야 '미디어 연결' 창이 안 뜬다.
- **폴더 이름을 도구가 바꾸지 않는다.** 이름 변경은 사용자가 캡컷 안에서 한다.
  캡컷이 자기 DB 까지 같이 고쳐야 하기 때문이다. 바꾼 뒤에 `수리` 를 돌린다.
- 백업 사본을 드래프트 폴더 **안에** 만들지 마라. '가장 깊은 사본' 규칙에 걸려
  백업을 진짜 파일로 읽는다.

## 4. 캡컷은 비디오 트랙을 배열 순서대로 늘어놓는다

`target_timerange.start` 를 보고 배치하는 게 아니다. 세그먼트를 배열 **끝에**
덧붙이고 시각만 앞으로 적어 두면, 캡컷이 열면서 배열 순서대로 다시 깔아
타임라인이 통째로 어긋난다.

실제로 오프닝·무음화면·클로징 12개가 뒤로 밀리고 강의가 0초로 당겨졌는데,
자막·배경음악·강조는 절대시각 그대로여서 28초씩 벌어졌다. 사용자 화면에는
강의 슬라이드 위에 오프닝 제목과 음악만 얹혀 있었다.

- 쓰기 전에 `normalize_draft.apply(d)` 를 부른다. 모든 트랙을 시각순으로
  정렬하고, 한 트랙 안에서 겹치는 텍스트·스티커·오디오는 새 트랙으로 뺀다.
- 겹침을 그대로 두면 캡컷이 자기가 트랙을 쪼개는데 **이름 없는 트랙**이 생겨
  다음 작업이 어느 게 자막인지 분간을 못 한다.

## 5. 소재를 다운로드 폴더에 뒀다

드래프트가 그 경로를 직접 물고 있어, 다운로드 폴더를 정리하는 순간 그 강의가
통째로 무음이 되거나 미디어 연결 창이 뜬다.

원본 mp4·보정 wav 는 로컬 고정 경로에 둔다. 이미 물려 있으면
`relocate_media.py` 로 옮긴다. 복사 후 크기 확인, 경로 수정, 존재 재확인,
원본 삭제 순서라 중간에 어긋나면 멈춘다.

클라우드 동기화 폴더도 피한다. 클라우드 필터를 거쳐 재생이 무겁고, 다른 PC 와
경로가 달라 드래프트가 안 열린다.

## 6. 판(버전)을 캡컷 목록에 쌓았다

`완성본(0824)`, `완성본(0825)` 식으로 목록에 날짜를 쌓으면 두 가지가 터진다.
캡컷에서 이름을 바꾸면 폴더가 통째로 옮겨져 안의 절대경로가 끊긴다(3번).
폴더 안에 판이 두 벌로 갈라지면 목록 항목이 옛 사본을 물기도 한다. 사용자
눈에는 "최종본이 사라졌다"로 보인다.

캡컷 목록에는 살아 있는 최신 하나만 두고, 역사는 목록 **밖**에 남긴다.

```
python src/draft_snapshot.py 저장 <드래프트> <메모>
python src/draft_snapshot.py 목록 <드래프트>
python src/draft_snapshot.py 복원 <드래프트> <판이름>
```

저장 위치가 캡컷 목록 밖(`_lecture_autocut_snapshots`)이라 잘못 열 일이 없다.
한 판에 십수 MB 로, JSON 만 담고 소재는 원래 자리에 그대로 둔다. 목록에 길이와
자막 수가 같이 나와 어느 판인지 구분된다. 복원은 되돌리기 전 상태를 자동으로 한
판 남기고, 끝나면 경로 수리까지 돈다.

**폴더 안에 판이 갈라졌는지도 본다.** 최상위 `draft_content.json` 과 하위 작업
사본의 길이·자막 수가 다르면 목록이 옛것을 열고 있다.

## 7. 성공한 척하는 단계

효과 모듈을 호출하며 두 번째 인자를 잘못 넘겨 `dry=True` 로 돌린 적이 있다.
슬라이드 덮개와 자막 교정이 통째로 빠졌는데 로그는 정상이었다. "덮을 슬라이드
4장" 까지만 찍히고 "4장 덮음" 이 없는 걸 아무도 못 봤다.

단계마다 **한 일의 개수**를 찍고, 0이면 이상하게 여겨라.

## 8. 랩탑이 옛 코드로 돌았다

수정한 버그가 다른 PC 에서 되살아났다. 그 PC 의 저장소가 수정 커밋을 못 받은
채 드래프트를 다시 만들어 옛 값이 그대로 들어갔다.

**다른 PC 에서 작업하기 전에 `git pull` 부터 한다.**

## 알아둘 것

- **STT 는 반복 발화를 지운다.** Whisper 는 같은 문장이 연달아 나오면 반복 억제
  필터가 하나를 없앤다. 그래서 전사본만 봐서는 재발화를 못 찾는다.
  `find_hidden_retakes.py`(늘어난 단어 흔적)와
  `transcribe_per_segment.py`(덩어리별 독립 전사)로 잡는다.
- **Whisper 는 문장 안 단어 간격을 0.00 초로 붙인다.** 실제 쉼이 안 보이므로
  자막은 간격이 아니라 한국어 어미·조사로 끊는다(`caption_split.py`).
- **전사에는 환각이 섞인다.** 조용한 구간에서 「시청해주셔서 감사합니다」
  「~및 광고를 포함하고 있습니다」 같은 상투구를 지어낸다. 잘라낼 소리가 없으므로
  영상은 그대로 두고 자막에서만 뺀다. 삭제 지시에 `"kind": "hallucination"` 을
  달면 빌드가 알아서 처리한다.
- **torch 는 한글 경로의 모델을 못 읽는다**(errno 42). 모델은 `models/` 같은
  ASCII 경로에 두고 로드한다.
- **wav 라고 16kHz 모노가 아니다.** 편집본에서 뽑은 wav 는 44.1kHz 스테레오다.
  확장자만 보고 단정하면 바이트를 잘못 읽어 소리가 3배 느려지고 좌우가 뒤섞인 채
  전사된다. 글자는 그럴듯한데 시각이 전부 틀린다. 도구가 헤더를 읽어 변환한다.
- **드래프트는 만든 PC 에서만 열린다.** 원본 mp4 경로가 절대경로로 박히기
  때문이다. PC 를 옮겨 편집하려면 원본을 같은 경로에 두거나 그 PC 에서 드래프트를
  다시 만든다. 계획 JSON 은 작으니 깃으로 주고받는다.
