# 편집 노하우가 쌓이는 곳

노하우는 세 층으로 나눠 둔다. 새로 배운 것이 생기면 어느 층인지부터 정한다.

| 층 | 무엇 | 어디 | 공개 |
|---|---|---|---|
| 공통 | 어느 강의·플랫폼에나 쓰는 도구와 규칙. 컷, 전사 검증, 검산, 효과, 캡컷 안전 | 이 저장소 `src/` `docs/` | 공개 |
| 플랫폼 | 납품 규격, 오프닝·엔딩 형식, 참조 드래프트 이름, 검수서에서 배운 것 | 플랫폼 프로젝트 폴더의 `규격.md` 와 `profiles/<플랫폼>.json` | 비공개 |
| 강의 | 차시별 판정, 사용자 편집과의 대조, 남은 일 | 강의 프로젝트의 `HANDOFF.md` 와 `work/` | 비공개 |

되풀이되는 함정은 에이전트 메모리에 한 줄씩 요약해 두고, 자세한 것은 위 문서를 가리킨다.

## 어느 층에 넣나

- 두 플랫폼 이상에서 같으면 공통으로 올린다. 한 곳에서만 확인했으면 플랫폼 층에 두고
  "다른 데서도 같은지 확인할 것"이라고 적는다
- 플랫폼 문서에만 있는 숫자(자막 크기, 오프닝 길이, 전환 종류)는 코드에 박지 않는다.
  계획 파일이나 프로필로 넘긴다
- 강의 내용(전사 문장, 교안 문구, 강사 이름)은 공통 층에 넣지 않는다. 예를 들어야 하면
  낱말 몇 개로 줄이거나 설명으로 바꾼다

## 새 노하우를 넣는 순서

1. [피드백-원장.md](피드백-원장.md) 에 한 줄: 날짜, 무엇이 틀렸나, 까닭, 규칙, 막는 곳
2. **규칙은 문서보다 도구에 먼저 넣는다.** 검산 항목이나 멈춤 조건으로 만든다.
   문서에만 있으면 다음에 또 건너뛴다. 이 저장소의 사고 대부분이 "문서에는 있었다"였다
3. 문서에는 까닭과 실측값을 적는다. 숫자의 정본은 코드다
4. 플랫폼·강의 것은 비공개 폴더로 보내고, 공통 문서에서는 가리키기만 한다

## 다른 스킬에서 가져온 것

남의 스킬을 볼 때는 **우리가 실제로 겪은 문제를 푸는지**로 고른다. 인기나 기능 수로 고르지 않는다.

| 가져온 것 | 우리 쪽 도구 |
|---|---|
| 렌더한 결과를 보여 주기 전에 스스로 검사, 3번까지만 | `render_preview` · `self_check` |
| 판단할 때만 쓰는 구간 보기(프레임 띠·파형·낱말) | `timeline_view` (dB 선·남는 곳·박스를 더함) |
| 효과는 그 말을 할 때 다 떠 있게 | `bake_builds.place_reveal`, 박스 선행 |
| 목표 길이와 구조로 덜어 내고 합계를 다시 보고 | `length_budget` (우리는 후보표를 사람이 고른다) |
| 방향을 먼저 확인받기 | SKILL.md 방향 확인 |
| 지킬 규칙과 예시 값을 나눈 문서 | SKILL.md 반드시 지킬 편집 규칙 |

| Scribe 전사(말 그대로, 시각 정확) | `transcribe_scribe`. 한 강의로 비교해 채택했다(시작 시각 90% 오차 0.51→0.09초, 지어낸 말 16→2). 다만 되풀이를 지워서 `fill_uncovered` 로 메운다. 수치는 SKILL.md 2단계 |

| 안 가져온 것 | 까닭 |
|---|---|
| 컷을 낱말 경계에 맞추기 | Scribe 시각 오차(50~100ms)를 전제로 한다. 한국어 Scribe 도 90%가 0.09초 안이라 쓸 만하지만, 우리는 파형 무음에서 자르는 쪽이 이미 검산을 통과했다. 낱말 시각은 판정과 자막에만 쓴다 |
| 색보정·짧은 대문자 자막·Remotion/Manim 애니메이션 | 원격연수에는 안 맞는다(말자막 금지, 화면 녹화). 다른 영상에서는 쓸 수 있다 |
| 한 파일로 끝까지 렌더하기 | 우리 결과물은 캡컷 드래프트다. 사람이 마무리한다 |
