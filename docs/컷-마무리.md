# 러프컷을 내놓기 전에

지적을 두 번 받았다. 2026-09-20 에는 "말 꼬임이 그대로 남아 있다", 2026-09-23 에는
"쉼 규칙을 안 따랐고 말 중간에 잘린다". 두 번 다 도구가 모자라서가 아니라
**단계를 건너뛰었거나 결과를 안 재서** 생겼다.

3차(09-20)에 쓴 방법 가운데 두 가지, 낱말 빈틈에서 자르기와 컷 지점을 소리 세기로
밀기는 4차 지적의 원인이었다. 아래에는 4차에서 검산을 통과한 방법만 적는다.

## 1. `fill_missing_words` 는 선택이 아니다

통짜 위스퍼는 **말을 통째로 흘린다.** 한 강의에서 덩어리 69개, 낱말 261개가 빠져 있었다.
이걸 안 메우면 다음이 줄줄이 어긋난다.

- 재발화 검출이 그 구간을 못 본다. 같은 말을 세 번 했는데 두 번만 보여 하나가 남는다
- 컷 계획이 **"말이 없는 블록"으로 오해한다.** 실제로는 실패 테이크가 들어 있다
- 실측: 메우기 전 "말 없는 블록" 63개였는데 메운 뒤 17개로 줄었다. **46개가 실패 테이크였다**

```bash
python src/fill_missing_words.py <words.json> <missing.json> <words_full.json>
```
**메운 뒤에는 4단계부터 `_words_full.json` 을 words.json 자리에 쓴다.**
재발화 검출도 이 파일로 다시 돌린다(후보가 94개에서 112개로 늘었다).

## 2. 쉼 규칙이 실제로 먹었는지 본다

`cut_planner` 는 컷마다 문장 끝인지 가려서 쉼을 달리 남긴다. 문장 중간 0.20초,
문장 끝 0.70초, 장면이 바뀌는 곳 1.20초. 값은 [컷-파라미터.md](컷-파라미터.md).

예전에는 문장부호로만 가렸다. 위스퍼는 한국어에 부호를 잘 안 찍는다. 한 강의 전사가
부호 2.9% 였고, "부호가 3% 미만이면 모든 컷을 문장 끝으로 본다"에 걸렸다.
문장 중간 쉼이 한 곳도 0.20초로 깎이지 않았다(272곳 중앙값 0.70초).
계획기는 "문장 중간 0곳"을 찍었는데 아무도 읽지 않았다.

지금은 종결어미(-니다, -요, -죠, -다 …)로도 가린다. **컷이 20곳 넘는데 문장 중간이 0곳이면
계획기가 멈춘다.** 계획기가 찍는 "문장 중간 N곳 · 끝 M곳"을 반드시 읽는다.

## 3. 덩어리 한가운데는 진짜 무음에서만 나눈다

삭제 지시가 발화 덩어리 한가운데에 걸리면 `cut_planner` 는 자르지 못한다
(`delete_overlap` 0.5: 덩어리 절반 넘게 걸려야 뺀다). 꼬리가 남는다.

3차에서는 이걸 **낱말 시각의 빈틈**으로 잘랐다. 위스퍼 낱말 시각은 ±0.3초, 심하면 1초
어긋난다. 컷 지점 904곳 중 84곳이 말 위에 떨어졌고, 강사가 문장 끝 서술어 세 곳을
손으로 되살렸다. 컷 지점을 소리 세기로 조금씩 미는 보정도 말 위의 컷을 없애지 못했다.

지금은 `refine_speech.py` 가 나눈다.

- `audio_levels.py` 로 10ms 단위 세기(dBFS)를 잰다
- 삭제 경계 근처에서 **-50dB 아래로 40ms 이상** 조용한 곳을 찾아 거기서 덩어리를 나눈다
- 그런 곳이 없으면 -45dB 아래 20ms 이상을, 지시 시각 ±0.25초 안에서만 받는다
- 둘 다 없으면 **나누지 않는다.** 말이 이어져 있다는 뜻이다. 목록으로 남겨 사람이 듣는다
- 블록 가장자리가 소리 위면 `snap_edges` 가 말 아닌 여유 안에서만 무음 쪽으로 옮긴다

나눈 결과를 speech.json 대신 `cut_planner` 에 넘기면 덩어리 경계가 모두 무음이므로 컷 지점도
전부 무음이 된다.

```bash
python src/refine_speech.py <speech.json> <words.json> <wav> <speech_refined.json> <삭제지시.json>... --levels <세기캐시.npy> --report <미해결.json> --snapped <옮긴지시.json>
```

알아 둘 것

- 녹음에 노이즈 게이트가 걸려 있으면 무음이 -120dB 로 뚜렷하다(말 중앙값 -34dB). 기준을 잡기 쉽다
- **된소리·파열음 앞의 폐쇄(ㅉ·ㄸ·ㅃ)는 낱말 안에서도 40ms 무음을 만든다.** 거기서 나뉘면
  0.3초 미만 조각이 남아 "넷-" 처럼 들린다. 남는 조각의 세기를 재서 잡고, 그 지시를 고쳐 적는다
- 위스퍼 환청(「시청해 주셔서 감사합니다」 류)은 소리째 지우면 진짜 말까지 지운다.
  **자막에서만 뺀다**(caption_only)

## 4. 들어 보고 고친 지시는 정확한 시각으로 적는다

판정을 사람이 고치면 `exact` 로 표시한다. 충돌 해소기(`resolve_delete_conflicts.py`)는
겹치는 지시를 넓게 합치는데, exact 지시는 건드리지 않는다. 안 그러면 고친 것이 되돌아간다.

## 5. 들리는 대본을 끝까지 읽는다

검산기가 못 잡는 헛시작과 되풀이가 있다. 컷 계획대로 잘랐을 때 **실제로 들리는 말**을
덩어리 단위로 뽑아 처음부터 끝까지 읽는다. 일부만 남은 덩어리와 0.35초 미만 조각의 세기를
함께 적어 두면 어디가 씹혔는지 보인다. 4차에서 이렇게 25곳을 더 잡았다.

## 6. 사용자가 손본 편집본은 정답지다

사용자가 일부라도 직접 편집했으면 **그 구간을 그대로 가져다 쓰고, 나머지에 규칙을 배운다.**
덮어쓰지 않는다.

```bash
python src/diff_user_cuts.py <드래프트> <keep_ranges.json> <words.json> --json <정답지.json>
```

한 강의에서 강사가 앞 1분 20초를 손보셨고, 대조해 보니 지운 것이 세 갈래였다.

| 갈래 | 내용 |
|---|---|
| 말 없는 블록 | 전사에 낱말이 안 달린 블록. 실은 전사가 흘린 실패 테이크였다 |
| 낱말에 붙은 재촬영 신호 | '다시' 가 앞말에 붙어 한 낱말로 전사되면(「○○다시」) 검색에 안 걸린다 |
| 짧은 false start | 다음 블록의 첫머리를 되풀이하는 1~3초짜리 |

**같은 말을 두 번 했을 때 늘 뒤 테이크가 낫지는 않다.** 강사는 앞 테이크를 남기고
뒤 테이크를 지우셨다. 교안 대본과 맞는 쪽이었다. 검출기 판정과 다르면 **대본을 대조한다.**

사용자가 옮겨 둔 자막이나 트랙이 있으면 다시 빌드할 때 떠 두었다가 도로 넣는다.

## 7. 검산 게이트 `final_check`

빌드 전에 돌린다. 기준을 넘으면 0 이 아닌 값으로 끝난다.

```bash
python src/final_check.py <keep.json> <words.json> <speech.json> <wav> --levels <세기캐시.npy> --deletions <판정.json> --takes <persegment.json> --report <검산.md>
```

| 항목 | 기준 | 4차 실측 |
|---|---|---|
| 소리 위(-45dB 초과) 컷 지점 | 0곳 | 891곳 중 0 |
| 문장 중간 쉼 | 0곳이 아니고 중앙값 0.30초 이하 | 263곳 · 중앙 0.20초 |
| 문장 끝 쉼 | 참고 | 169곳 · 중앙 0.70초 |
| 삭제 잔여 | 0.5초 이하 | 0초 |
| 연달아 같은 낱말 | 0건 | 0건(오탐 7건은 들어 보고 목록에 적었다) |
| 연달아 같은 문장 | 0건 | 0건 |

**같은 낱말이 0건이어도 소리 위 컷이 있으면 "말이 씹혔다"는 말을 듣는다.** 둘 다 본다.
앞에 인트로를 붙였으면 `--offset` 으로 시각 차이를 주고, 사람이 손본 구간은 `--skip` 으로 뺀다.
